### N1 — Page titles and descriptions are raw TeX (live)

- **Where:** `gather.lua:1071-1073` and `:1081-1083` keep the raw braced argument. `gather.lua:1351` and `:1357` store it as metadata unchanged.
- **Where it leaks:**
  - `render.lua:715-716` and `:730-731` only HTML-escape it before it goes into `<title>`, `og:title`, `twitter:title`, `data-pagefind-meta="title[content]"` and the description metas.
  - `merge_meta.lua:214-222` uses it as the `title` field of every label record and every keyword record.
- **Evidence in current `www/`:**
  - 9 pages have `--` in `<title>` (e.g. `www/hallLittlewood.htm:4` reads `Hall--Littlewood polynomials | SymCat`).
  - 19 pages have `--` in `content="…"` attributes (e.g. `www/hivert.htm:7`).
  - The new feed is inconsistent within a single page. `www/site-keywords.json:863-865` has `"title":"Touchard--Riordan polynomials"`, while `:1140` has `"phrase":"Touchard–Riordan polynomials"` (Pandoc converted the phrase, not the title).
  - 40 keyword-feed lines, 92 lines in `site-labels.json` and 6 in `polynomial-relations.json` contain `--Riordan`/`--Littlewood`/`--Tsetlin`.
  - No `\`, `$` or `{` titles exist today, but `\&`, `~`, accents or `$q$` in a title would leak the same way.
- **Impact:** Raw TeX shows in browser tabs, search snippets and social cards. Both public feeds consumed by arXiv++ carry it too.
- **Minimal fix:** In gather, convert the title and description to plain text once: `pandoc.utils.stringify(pandoc.read(arg, "latex"))`, the same approach as the `\name` fix. Store the result as `MetaString`.
- **Regression test:** Give the unit fixture `\metatitle{Hall--Littlewood \& co}`. Assert:
  - the HTML contains `<title>Hall–Littlewood &amp; co | SymCat</title>`;
  - every fixture keyword and label record has `title == "Hall–Littlewood & co"`.

  Add a lint rule that rejects `--`, `\` or `{\` inside `<title>` and `content="…"`.

### N2 — Merge depends on BibTeX JSON without declaring it

- **Code path:**
  - `merge_meta.lua:810` calls `relation_graph.render_page`.
  - `relation_graph.lua:325-326` calls `bibhandler.build_bibliography_HTML(refs_json, graph.references)` with no BibTeX path.
  - `bibhandler.lua:412-415` falls back to `BIBTEX_JSON` (or `./temp/bibtex-entries.json`) and loads it **strictly**, so a missing file raises a Lua `error()`.
  - The live relation page has a bibliography, and the test fixture's relations cite `Jacobi1841`/`Cauchy1815`, so both merges take this path.
- **Rules:** neither the site merge (`Makefile:115`) nor the test merge (`Makefile:143`) lists `$(BIBTEX_JSON)`. The September D16 fix replaced it with `REFS_JSON`, on the old audit's incorrect claim that merge never reads it.
- **Triggers:**
  1. `make clean && make meta` never schedules `BIBTEX_JSON`. Merge writes the first eight outputs, then crashes at the relation page. This is deterministic by code; by GNU semantics, `.DELETE_ON_ERROR` should then remove the changed outputs.
  2. Under `-j8`, `all` and `unittest` build it only because renders need it, with no ordering against merge. In practice this probably does not fail (needs execution).
  3. A change to `bibtex_extract.lua` alone does not regenerate the BibTeX controls on `polynomial-relations.htm`, which go stale.
- **Fix:** Add `$(BIBTEX_JSON)` to both grouped merge rules alongside `$(REFS_JSON)`, and pass `BIBTEX_JSON` explicitly to the test merge for symmetry.
- **Regression test:** `make -n -W temp/bibtex-entries.json meta` should schedule the merge. A scratch `make clean && make meta` should succeed.

### N3 — Keyword export edge cases (needs execution)

- `gather.lua:1326-1333` skips only `Space` before checking for a following `label` span. Pandoc's LaTeX reader turns a single source newline into `SoftBreak`. So `\defin{term}` at the end of a line, followed by `\label{x}` on the next line, would silently export a page-level `href` instead of `#x`.
- Definitions inside `rawtabular` cells become HTML strings before the finalizer runs (`gather.lua:1232-1235`). The `Inlines` walk (`:1312`) never sees them.
- **Probe and regression:** add `\defin{Line-break term}` + newline + `\label{lineBreakTerm}` to the fixture, and expect `unittest.htm#lineBreakTerm` in `site-keywords.json`. If confirmed, skip `SoftBreak` as well as `Space`.

### N4 — Production feeds are not validated

- `tests/check_unittest.lua:27-45` checks only the fixture catalogue, and only for the substring `x_1`.
- `tests/lint_html.lua` never opens `www/site-keywords.json` or `www/site-labels.json`. The HANDOFF records the check that all 1,126 references resolve as a one-off manual verification.
- **Suggestion:** a lint pass over both feeds that asserts:
  - `schema_version == 1`;
  - every `href` page exists in `www/` and its fragment appears as `id="…"`;
  - no `\`, `{`, `$`, `@@` or `--` appears in `phrase` or `title`.

### N5 — Merge reruns on every build

- `merge_meta.lua:83-90` deliberately leaves unchanged outputs untouched.
- After any edit that does not change metadata, all nine grouped targets stay older than the regenerated page JSON (`Makefile:115`), so every later `make` reruns the merge (probably about a second, not measured).
- The sitemap (`merge_meta.lua:632`) and the relation page (`relation_graph.lua:334`) contain today's UTC date. The first rerun on a new day therefore rewrites them, and `polynomial-relations.htm` is a Pagefind prerequisite (`Makefile:220`), so the whole search index is rebuilt.
- **Fix:** drive the merge from a success stamp that is touched every time, keeping the content-stable outputs that renders depend on. Check the result with `make -d`. Separately, date both pages from their inputs rather than the wall clock.
